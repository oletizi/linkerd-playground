# Controller rulings — cert-hygiene lab, slice 2

Decisions taken during the execution of [the slice 2 plan](../plans/2026-09-11-cert-hygiene-lab-slice-2/README.md), recorded verbatim from the execution ledger. They are listed in the order they were made.

A ruling was needed whenever the plan, the design or a review left a question the execution could not answer from the text: a defect in the plan's own code, a stop gate that fired for the wrong reason, a measurement that could not be taken as specified, or a finding whose fix would have cost more than it saved. Each says what was decided, why, and what it costs if it was wrong.

Two of them are not controller rulings and are marked as such in the ledger: the user approved the forced-reconnect phase for the webhook scenario (recorded in the design's § 12.3), and the user chose to run this plan with a fresh agent per task.

The largest ones, for a reader who wants only those:

- **The first stop gate was a false alarm.** The webhook-certificate discovery compared CA certificates byte for byte, and a trailing newline is lost through the Kubernetes API. Fixed to compare certificates; the original run stays committed as the record.
- **The webhook scenario gained a forced-reconnect phase** (user-approved) after the first throwaway run showed expired webhooks still working on connections the API server had already opened.
- **The hard-swap scenario's first stage could never be satisfied as designed.** It waited for a certificate-refresh error counter that the real failure never touches, because the proxy cannot reach the identity service at all after the swap. It now accepts the proxy log's own record of that failure.
- **A run that fails the private-key check must not be committed.** The plan's pre-commit check only looked for plain PEM text; a key hidden in base64 would have passed. Every run commit from the throwaway phase onward passes a full scan first.
- **The `linkerd check` 60-day threshold is reported as only partly reproduced.** The warning firing below the boundary is evidence; the check passing above it was seen only in a run that the harness itself stamped invalid.
- **The harness tree must not be edited after the freeze.** Every evidence run records the hash of the harness it ran against; editing the harness would invalidate all nine runs against their control. The final review's findings were therefore fixed only in the article pages.
